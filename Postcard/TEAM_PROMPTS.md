# Postcard — teammate prompts

## Shared brief and contract

We are building **Postcard**: the closed Duo shows a photographic postcard front; opening reveals the personal message; closing seals the draft. Sending is a separate, explicit action. Grandma should receive a link she can open without an account, then tap to turn the postcard over.

**Primary recipient flow:** publish to the backend and share its HTTPS link. The offline HTML attachment is only a fallback; it is not the primary Grandma experience because attachment previews vary across apps.

**Current state:** The native SwiftUI prototype is in `Postcard/Postcard/`. `PostcardApp.swift` contains the main experience, photo selection, rendering, and Duo hinge behavior. `PostcardSending.swift` implements real native image sharing, supported-device Messages composition, and an offline HTML attachment with a flip interaction. These do not constitute a hosted recipient service. **The API described below is a proposed integration contract, not an existing API.** Confirm the latest branch before editing.

**Ownership:** Design owner supplies visual direction and assets. Z owns the main SwiftUI file and native API integration. Zabir owns a new `DuoInteractionController.swift`; coordinate integration with Z rather than editing Z's file concurrently. Pranav owns `backend/` and `web/`.

**Proposed v1 API:**

- `POST /api/postcards`: multipart fields `photo` (JPEG/PNG), `recipient`, `sender`, `message`, `destination`. Explicitly publishes a postcard. Returns `{ id, url }`, where `url` contains an unguessable public read token. Use `Idempotency-Key` to avoid duplicate publishes on retries.
- `GET /api/postcards/:token`: returns `{ recipient, sender, message, destination, photoUrl, expiresAt }`; `photoUrl` is a short-lived signed image URL. Missing, deleted, and expired cards return the same 404 response.
- Publisher ownership and deletion require authenticated backend authorization; the public read token must never permit mutation. Default expiry: 30 days. The receiver needs no login.
- Native code configures the service base URL rather than hardcoding a developer host. Publish errors preserve the draft and offer the existing image share fallback. Recipient and sender are display names, not verified delivery addresses.

Each teammate: create a distinct branch, commit only your owned files, run relevant checks, push your branch, and open a draft PR. **Do not merge.** If repository/remotes or credentials are unavailable, report that and provide the local commit/patch; never invent a pushed PR. Never commit secrets or credentials.
